## Design read (as found)

The project ships a dark, cyan/blue "cyber-minimalist" developer portfolio: blueprint grid background, gradient text, glass cards, radial glow orbs, Geist/Geist Mono, Lucide icons, and looping animation. `DESIGN.md` describes a different direction (engineering blueprint: `#0b1623`, orange `#ff9f30` accent, JetBrains Mono, 0px radius). The implementation does not follow `DESIGN.md`, so several decisions lack a written reason (R-31, R-37).

Priority mapping used below: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Lock = LOW.

---

## HIGH (Hard Gate)

### 1. Em dashes in user-facing copy (R-02)
The character `—` appears in rendered UI text: page titles, post summaries, and article bodies.

Evidence:
- `dictionaries/en.json:3,119,132` and `dictionaries/id.json:3,119,132` (metaTitles)
- `content/blog/rebuilding-portfolio.mdx:4,12,32` and `.id.mdx:4,11,28`
- `content/projects/portfolio-website.mdx:3,17,31` and `.id.mdx:3,16,26`
- `app/[lng]/journal/[...slug]/page.tsx:25` (title template)

Reason: R-02 forbids the em dash in text the UI ships. Replace with comma, period, colon, or parentheses. Documentation files (`DESIGN.md`, `AGENTS.md`, skill files) are outside this finding.

### 2. Primary navigation is missing on mobile (R-24, R-03)
`NavigationBar.tsx:49` hides all three primary links with `hidden md:flex`, and no mobile menu or replacement exists. On phones the only route to Journal and Projects is the footer.

Reason: navigation must stay usable at every breakpoint and must point to real destinations. Add a working mobile menu, or keep the links visible at small widths.

### 3. Dead controls (R-26)
- `Footer.tsx:98`: `<a href="#">Resume</a>` goes nowhere.
- `PortfolioHero.tsx:129`: the "scroll hint" is a `div` with `cursor-pointer` and no click handler.

Reason: every interactive element must do something or be removed. Link the resume to a real file or label it "Coming soon"; turn the scroll hint into a real anchor or remove it.

### 4. Muted text fails WCAG AA contrast (R-25)
`--color-muted: #64748b` on `--color-void: #0f1115` is about 4.0:1, below the 4.5:1 minimum for normal text.

Evidence: `globals.css:25`; used for dates and metadata in `Notes.tsx:70`, `app/[lng]/journal/page.tsx:80`, `app/[lng]/journal/[...slug]/page.tsx:100`, `Footer.tsx:36,94`, and detail pages.

Reason: small metadata text is below the required ratio. Lighten `--color-muted` or use `--color-secondary` for small copy.

### 5. Loading and error states are absent (R-27)
Only empty states exist (`Projects.tsx:136`, `Notes.tsx:112`, `app/[lng]/journal/page.tsx:120`, `app/[lng]/projects/page.tsx:158`). There is no `loading.tsx`, `error.tsx`, or `not-found` handling beyond Next.js defaults anywhere in `app/`.

Reason: data views need empty, loading, and error states. Add route-level loading and error boundaries with a cause and next action.

### 6. Semantic and accessible-name defects (R-39)
- The home page has two `h1` elements: `PortfolioHero.tsx:36` and `Projects.tsx:37`.
- The hero heading order is `h2` (greeting) before `h1`: `PortfolioHero.tsx:33` then `:36`.
- Navbar icon-only social links have no accessible name: `NavigationBar.tsx:89-91` (GitHub, LinkedIn, X). The SVG icons also lack `aria-hidden`.

Reason: one `h1` per page, no skipped heading levels, and every icon-only control needs `aria-label`. Add labels and demote the project section title to `h2`.

### 7. Fabricated system-status claim (R-36, R-38)
`Footer.tsx:36-42` shows "ALL SYSTEMS NOMINAL" / "SEMUA SISTEM BERJALAN NORMAL" with a pulsing dot, implying live monitoring that does not exist.

Reason: this presents an operational claim as fact. Remove it or back it with real status data. The pulsing dot is also decorative (R-13, R-19, R-31).

### 8. Unverified statistics in experience copy (R-17)
The experience entries assert metrics with no source in the repo: 60,000+ views, 3,000+ participants, 120+ users, 80,000+ areas, 165+ items, 20%, 40%, 5+ components.

Evidence: `dictionaries/en.json:49-79`, `dictionaries/id.json:49-79`.

Reason: R-17 forbids statistics without a real source. These may be true and come from the owner's CV; confirm each, or remove the numbers. Empty is better than unverifiable.

## MEDIUM (Purpose-Gate)

### 9. Cyan-to-blue gradient used as the default color treatment (R-01)
`.text-gradient` (`globals.css:186-194`) is applied to the hero role and to the gradient half of nearly every section title.

Evidence: `PortfolioHero.tsx:39`, `PortfolioSkills.tsx:57`, `PortfolioExperience.tsx:61`, `Projects.tsx:38`, `Notes.tsx:48`, `app/[lng]/journal/page.tsx:58`, `app/[lng]/projects/page.tsx:50`, plus both detail pages. Radial glow orbs repeat on every page (`PortfolioHero.tsx:25,61`, `PortfolioSkills.tsx:47`, `PortfolioExperience.tsx:51`, `Projects.tsx:26-27`, `Notes.tsx:37`, `Footer.tsx:19`, `app/[lng]/journal/page.tsx:46-47`, `app/[lng]/projects/page.tsx:36-38`).

Reason: this is the default AI gradient, reused as the primary palette instead of a hierarchy tool. Use the accent at one key moment, or adopt the `DESIGN.md` orange with a written reason.

### 10. Blueprint grid background without a confirmed decision (R-07, R-37)
`globals.css:100-104` paints a 40px grid on `html`. `DESIGN.md` prescribes it, so a direction exists, but the implementation no longer matches that direction.

Reason: a grid is allowed only when it serves the product identity. Confirm with the owner whether the blueprint identity is the brand; if yes, record the override and align the rest of the palette to it; if no, remove the grid.

### 11. Glassmorphism exceeds the dose cap (R-10)
`.glass` (`globals.css:197-208`) is applied to the nav pill, the hero contact button, every skill card, every experience card, every project card, every note card, every journal card, empty states, and MDX callouts.

Evidence: `NavigationBar.tsx:76`, `PortfolioHero.tsx:54`, `PortfolioSkills.tsx:73`, `PortfolioExperience.tsx:95`, `Projects.tsx:51`, `app/[lng]/projects/page.tsx:63`, `Notes.tsx:60`, `app/[lng]/journal/page.tsx:71`, `Callout.tsx:18`.

Reason: glass should be an accent on 1-2 surfaces, not the surface for every component. Make most surfaces solid.

### 12. Glow applied across the whole page (R-13)
Glow appears on the background orbs, card hover shadows, badge hover borders, the ghost button hover (`globals.css:252`), the timeline node (`PortfolioExperience.tsx:86`), and the navbar shadow (`NavigationBar.tsx:40`).

Reason: glow is an attention amplifier; used everywhere it amplifies nothing. Reserve it for the single focal action.

### 13. Looping and template motion, with no reduced-motion guard (R-19, R-39)
- Infinite float: `FloatingKey.tsx:4`, `TechBadge.tsx:4`.
- Infinite pulse-glow orbs: `PortfolioHero.tsx:25,61`, `Projects.tsx:26`, `app/[lng]/journal/page.tsx:46`.
- Infinite flow: `PortfolioExperience.tsx:73`.
- Infinite ping: `Footer.tsx:38`.
- Infinite bounce: `PortfolioHero.tsx:129`.
- `animate-fade-up` on nearly every section and card.

`globals.css` has no `prefers-reduced-motion: reduce` block. This also contradicts `DESIGN.md` ("Motion 1/10 Static", "No entry animations").

Reason: motion must serve a written purpose and match the declared dial. Remove the loops, add a reduced-motion guard, and keep motion to hover feedback.

### 14. One icon library chosen for its look, plus generic glyphs (R-04)
Lucide is used throughout: `Cpu`, `Database`, `Terminal`, `GitBranch`, `BrainCircuit`, `Box`, `Server`, `LayoutTemplate`, `FolderGit2`, `BookOpen`, `Briefcase`, `Calendar`, `Languages`. The custom icons reuse the same thin rounded stroke style (`CustomIcons.tsx`).

Reason: the set reads as the default Lucide look rather than a product-specific choice, and several glyphs (CPU, database, brain) are generic category markers. Pick icons for content relevance or drop them.

### 15. Default typeface and wide-tracked uppercase labels (R-06)
`layout.tsx:9-17` and `globals.css:45-46` use Geist and Geist Mono, the Vercel defaults, while `DESIGN.md` specifies JetBrains Mono. Section eyebrows use `font-mono tracking-widest uppercase` (`PortfolioSkills.tsx:53`, `PortfolioExperience.tsx:57`, `Projects.tsx:33`, `Notes.tsx:43`, `app/[lng]/journal/page.tsx:53`, `app/[lng]/projects/page.tsx:45`).

Reason: the typeface is the framework default rather than a brand decision, and the wide-tracked uppercase label is a stock "technical" signal. Align to `DESIGN.md`, or write the reason for Geist and reduce the tracking.

### 16. Identical feature cards (R-14)
The skills section is four identical glass cards with the same icon box, padding, and layout (`PortfolioSkills.tsx:65-101`). Project and note cards also repeat one shape.

Reason: equal cards flatten the hierarchy; the strongest skill category cannot stand out. Vary one flagship card or use a list for supporting items.

### 17. Arrows on nearly every action (R-08)
`ArrowRight` and `ArrowUpRight` appear on the hero CTA, scroll hint, read-more links, project links, project cards, detail-page actions, and back links.

Evidence: `PortfolioHero.tsx:52,130`, `Notes.tsx:105`, `app/[lng]/journal/page.tsx:114`, `Projects.tsx:118,128`, `app/[lng]/projects/page.tsx:140,150`, `app/[lng]/projects/[...slug]/page.tsx:74,136`, `app/[lng]/journal/[...slug]/page.tsx:67`.

Reason: when every action has an arrow, the arrow stops signaling direction. Keep it only where a direction cue matters.

## LOW (Quality Locks)

### 18. Template-shaped section rhythm (R-05)
The home page runs hero, a 4-card skills grid, a timeline, a 3-column project grid, a 2-column notes grid, then a 4-column footer (`Footer.tsx:24`). Nearly every section is "title, subtitle, card grid", and the page order is the stock portfolio sequence.

Reason: `DESIGN.md` declares a low variance, so some uniformity is intentional, but the composition is still the default template. Vary composition or cut sections that only mirror the template.

### 19. Palette exceeds the 2-3 core colors plus one accent cap (R-29)
Active colors: cyan `#22d3ee`, blue `#3b82f6`, purple-400, green-400, yellow-400, plus the `DESIGN.md` orange and green. See `globals.css:29-32`, `PortfolioHero.tsx:83,95`, `PortfolioSkills.tsx:26,31`, `Callout.tsx:11`.

Reason: too many accents means none is the accent. Cap the palette and let one accent carry the page.

### 20. Radius scale does not match the design system (R-11)
`DESIGN.md:93` sets a 0px base radius, but the code uses `0.75rem` cards, `0.375rem` badges, `rounded-full` nav pills, `rounded-3xl` hero image, and `8px` keycaps (`globals.css:75-76,200,221,241`, `NavigationBar.tsx:66,76`, `PortfolioHero.tsx:64`, `globals.css:308`).

Reason: radius is being used as decoration rather than a consistent hierarchy scale. Define a small scale and align it to `DESIGN.md`.

### 21. Generic CTAs and buzzword copy (R-15, R-16)
CTAs: "Explore My Projects", "Get in Touch", "Read More", "View All Notes", "Read Docs". Copy: "robust, scalable digital systems", "comprehensive overview", "Technical Arsenal", "Digital Arsenal" (`dictionaries/en.json:11-13,16,19,84,92`, `dictionaries/id.json` equivalents).

Reason: the copy names no specific benefit. Replace with concrete actions and evidence.

### 22. Generic identity, close to popular developer-tool aesthetics (R-20, R-30)
Swap "IHY." and this could be any dark cyan-and-glass developer portfolio; the cyan gradient, glass, and glow recall Vercel/Linear styling. There is no identity motif tied to the owner.

Reason: identity must survive a logo swap. Adopt the blueprint/schematic identity from `DESIGN.md`, or another motif with a written reason.

### 23. Implementation diverges from `DESIGN.md` with no recorded reasons (R-31, R-37)
`DESIGN.md` specifies background `#0b1623`, accent `#ff9f30`, JetBrains Mono, and 0px radius. The code uses `#0f1115`, cyan `#22d3ee`, Geist, and `0.75rem` radius. No one-line reasons exist for the switch.

Reason: every major decision needs a written reason. Either reconcile the code with `DESIGN.md` or update `DESIGN.md` and record why. Under R-37, do not silently override the direction.
